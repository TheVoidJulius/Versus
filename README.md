## ⚡ Boot sequence

Welcome to **Versus**, a side-by-side AI response comparison workspace. Give two models the same prompt, inspect their answers, and vote for A, B, or a tie. No leaderboard pretending to be science: just the matchup and your judgment.

### 🎮 Inside the cabinet

| Arcade feature | Power-up |
|---|---|
| **Model matchup** | Pick two models and send them the same prompt concurrently. |
| **Prompt starters** | Drop in a sample prompt or write your own—up to 5,000 characters. |
| **Response arena** | Read both answers, see whether each is live or a local sample, and compare response times. |
| **Human verdict** | Choose **A wins**, **B wins**, or **It’s a tie**. |
| **Rematch history** | Reopen up to 10 recent matchups; history and votes stay in your browser. |
| **CRT cabinet** | Wake up the pixel-art welcome screen and toggle the scanline effect. |
| **Phone-friendly controls** | Play from narrow mobile screens through desktop layouts. |

### 🟣 Insert coin. Wake up. Choose.

1. Select **Insert Coin · Wake Up** to power the cabinet.
2. Hit **Start Match** to jump to the arena.
3. Enter a prompt—or grab a starter.
4. Choose a model for side A and side B.
5. Run the face-off, review both answers, and call it.
6. Reopen a recent matchup or clear your local arcade history.

**Keyboard shortcut:** `Ctrl + Enter` (or `Command + Enter` on macOS) runs a comparison while the prompt field is focused.

## 🚀 Start the local arcade

### Requirements

- Node.js **20.9+**
- Yarn Classic **1.x**

### Power on

```powershell
yarn install
yarn dev
```

Open [http://localhost:3000](http://localhost:3000).

No API key? No problem. Each unconfigured provider returns a **clearly labeled local sample** so you can explore the experience. Samples are not generated by AI and are never presented as live model responses.

## 🔌 Connect live providers

1. Create a local environment file:

   ```powershell
   Copy-Item .env.example .env.local
   ```

2. Add the keys for the providers you want to use:

   ```dotenv
   GROQ_API_KEY=your-groq-key
   OPENAI_API_KEY=your-openai-key
   ```

3. Restart the dev server and select a model from a configured provider.

| Provider | API key | Current model options in Versus |
|---|---|---|
| **Groq** | `GROQ_API_KEY` | GPT-OSS 20B · Llama 3.3 70B |
| **OpenAI** | `OPENAI_API_KEY` | GPT-4o mini · GPT-4.1 mini |

Keys are read by the server and never sent to the browser. If a provider key is missing, that side returns a labeled local sample. If a configured provider request fails, Versus shows the provider error instead of quietly substituting sample content.

> **Model IDs, availability, pricing, and quotas can change.** Check the provider’s current catalog before choosing a model.

- [Groq API keys](https://console.groq.com/keys) · [model catalog](https://console.groq.com/docs/models) · [rate limits](https://console.groq.com/docs/rate-limits)
- [OpenAI API keys](https://platform.openai.com/api-keys) · [model catalog](https://platform.openai.com/docs/models)

### 🛡️ Keep the cabinet keys safe

- Never commit `.env.local`; never expose provider keys through a `NEXT_PUBLIC_` variable.
- Live prompts are sent to the provider or providers you select. Avoid sensitive or confidential input.
- Provider data handling, retention, terms, and pricing are controlled by each provider and may change.
- AI output can be wrong. Verify important claims before relying on them.

## 🎨 Pixel-powered presentation

Versus takes its visual cues from retro arcade splash screens: a deep midnight-blue cabinet, electric cyan and magenta, sunny yellow highlights, chunky pixel decorations, scanlines, and a glowing **VS** core.

The welcome screen is interactive, not just a poster. Wake it up, watch the marquee change state, flip the CRT scanlines, and jump straight into a real comparison. The matchup, voting, and history controls remain the center of the experience.

Motion respects the operating system’s **reduced-motion** setting.

## 🧩 Under the hood

- **Next.js 15** App Router
- **React 19**
- **TypeScript**
- A validated `/api/compare` route that sends requests to providers from the server
- Parallel model calls with separate, explicit live/demo/error results
- Browser `localStorage` for up to 10 recent matchups and preference votes

### Build & verify

```powershell
yarn typecheck
yarn build
yarn start
```

Deploy to a Node.js host that supports Next.js route handlers. Configure provider keys in the host’s **server-side secret manager**, not in client-visible settings. Before making the comparison endpoint public, add host-level rate limiting and usage controls.

## 🗺️ Current level

Versus is a working early project—not an independent benchmark suite. It has no accounts, cloud-synced history, blind model labels, distributed API rate limiting, or automatic quality judge. Preference votes are personal feedback, not scientific proof that one model is universally better.
